GROUND CONTROL ARCHITECTURE - Perseverance rover in OmniLRS / Isaac Sim
Slide notes: data flow and functions

================================================================================
SLIDE 1 - ARCHITECTURE AND DATA FLOW
================================================================================

TITLE: Ground control: goals down, telemetry up

--------------------------------------------------------------------------------
THE CENTRAL CONSTRAINT (the "why" of the whole design)
--------------------------------------------------------------------------------

    Ground link .............  1 Hz
    Wheel control loop ......  30 Hz
    Mars one-way light time .  4-24 min (real mission)

    => Low-level control CANNOT run on the ground.
    => Ground sends GOALS ("drive 2 m"); the rover computes wheel motion itself.

    This one fact determines every boundary in the system.


--------------------------------------------------------------------------------

--------------------------------------------------------------------------------

  |         |                   |        |         |                       |

  Both containers run --network=host, so they meet on 127.0.0.1.


--------------------------------------------------------------------------------
UPLINK - telecommand path (event driven)
--------------------------------------------------------------------------------

  1. Operator issues command in Yamcs web UI
  2. Yamcs encodes it per the MDB          cfg/mdb/perseverance.xml
       wire format = ASCII command name + big-endian arguments
  3. UdpTcDataLink                          -> 127.0.0.1:10025
  4. CommandsHandler._tc_listener_loop()    daemon thread, never blocks physics
  5. MdbParsingService.decode_tc_payload()  bytes -> {name, arguments}
  6. CommandsHandler._execute()             dispatch via callback table
  7. PerseveranceCommander.<command>()      acknowledge + delegate
  8. PerseveranceDriveController.command_*() start the closed-loop goal

  7 commands:
      /Rover/motor/drive_straight     (linear_velocity m/s, distance m)
      /Rover/motor/drive_turn         (angular_velocity deg/s, angle deg)
      /Rover/motor/goto               (x, y in metres)
      /Rover/motor/stop
      /Rover/system/go_nogo           (GO / NOGO)
      /Rover/system/power_electronics (device, ON / OFF)
      /Rover/system/deploy_solar_panel(DEPLOYED / STOWED)


--------------------------------------------------------------------------------
DOWNLINK - telemetry path (1 Hz, simulation time)
--------------------------------------------------------------------------------

  1. IntervalsHandler fires on the Kit update stream, gated on SIM time
  2. PerseveranceTransmitter.transmit_*()   one method per telemetry group
       reads: Robot / RobotRigidGroup / subsystems / drive controller
  3. YamcsTMTC.transmit_to_yamcs()          error-guarded: a dead ground
                                            station must never stop the rover
  4. processor.set_parameter_value()        Yamcs LocalParameterManager
  5. ParameterRecorder + ParameterArchive   persisted to a docker volume

  41 parameters:
      pose / IMU ........ pose_ground_truth, imu_accelerometer/gyroscope/orientation
      mobility .......... motor_encoder, contact_force_* (6 wheels)
      power ............. battery_charge, net_power, current_draw_* ...
      thermal / comms ... temperature_* (6 faces), radio_rssi
      state ............. obc_state, go_nogo, solar_panel_state
      command feedback .. active_command, command_status,
                          command_distance_remaining, command_heading_error,
                          command_target

  NOTE: nothing is stored on the rover. Only what crosses the link survives.


================================================================================
SLIDE 2 - ONBOARD CONTROL LOOP
================================================================================

TITLE: The rover closes its own loop

--------------------------------------------------------------------------------
CONTROL LOOP - runs every physics step (30 Hz)
--------------------------------------------------------------------------------

    PerseveranceDriveController.update()
        |
        |  1. check interlocks .... go_nogo == GO
        |                           motor controller ON
        |                           motor health NOMINAL
        |                           (re-checked every step, not just at start)
        |
        |  2. read pose .......... robot_RG.get_pose_of_base_link()
        |                           quaternion -> heading of the forward axis
        |
        |  3. compute error ...... distance remaining / heading error
        |                           MEASURED, never dead-reckoned from time
        |
        |  4. solve geometry ..... AckermannModel.solve(v, curvature)
        |                           or .solve_point_turn(yaw_rate)
        |
        v  5. write joints ....... Robot.set_steer_angles()    4 corner joints
                                   Robot.set_wheel_velocities() 6 drive joints


--------------------------------------------------------------------------------
CLOSED LOOP vs OPEN LOOP - why it matters
--------------------------------------------------------------------------------

    Open loop (dead reckoning)      Closed loop (this design)
    ---------------------------     -----------------------------------
    stop after distance/velocity    stop when measured distance reached
    never reads the pose            reads pose every step
    drifts on slip and slopes       self-correcting
    goto(x,y) impossible            goto(x,y) works


--------------------------------------------------------------------------------
FOUR-CORNER ACKERMANN STEERING
--------------------------------------------------------------------------------

    6 drive joints  -> velocity control  (rad/s)
    4 steer joints  -> position control  (rad)   front + rear corners
    2 mid wheels    -> unsteered

    Turn centre placed on the lateral line through the MID axle.
      => mid wheels are always tangential, no special case needed
      => during a point turn they counter-rotate naturally

    Per wheel, with radius vector (dx, dy) to the turn centre:
        steer angle  d = atan2(dy, -dx)
        wheel speed  w = yaw_rate * hypot(dx, dy) / wheel_radius

    Result: wheels ROLL through the turn instead of skidding
      -> smooth arcs, far less terrain-dependent slip


--------------------------------------------------------------------------------
STATE MACHINE - reported as /Rover/command_status
--------------------------------------------------------------------------------

    IDLE ---> EXECUTING ---> COMPLETE      goal reached within tolerance
                  |
                  +--------> REJECTED      interlock blocked or dropped
                  |
                  +--------> ABORTED       manual takeover or NOGO

    Tolerances: 0.15 m (goto arrival), 0.05 m (straight), 2 deg (heading)


--------------------------------------------------------------------------------
CONTROL ARBITRATION - keyboard vs ground command
--------------------------------------------------------------------------------

    Both paths go through ONE controller, so they can never fight over joints.

    keyboard input present  -> takes over, aborts the running command
    keyboard idle           -> yields, the active command keeps driving

    (Models a local manual override of an autonomous drive.)


--------------------------------------------------------------------------------
KEY DESIGN POINTS FOR THE SLIDE
--------------------------------------------------------------------------------

  * Rate separation is the architecture: 1 Hz link, 30 Hz control loop
  * Ground issues goals; the rover owns execution
  * Command feedback closes the operator loop - status, distance remaining,
    heading error, and the echoed target all come back as telemetry
  * Interlocks are enforced AND reported: "refused because NOGO" is visible
    from the ground, not silent
  * Telemetry history lives only in the ground archive, as on a real mission
